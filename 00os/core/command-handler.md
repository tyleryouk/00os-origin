# 00OS Command Handler

## Overview

This component is responsible for identifying, parsing, and routing commands that use the 00OS terminal interface syntax (using the `>` prefix). It serves as the entry point for command processing within the 00OS system.

## Command Syntax Detection

When a user enters a message, this handler checks if it matches the command syntax:

```
> [command] [subcommand] [arguments] [--flags]
```

Examples:
- `> help`
- `> file list /00os/processes`
- `> system status --detailed`

## Command Processing Flow

1. **Detection**: Identify if the input starts with the command prefix (`>`)
2. **Tokenization**: Split the command into its constituent parts (handled by `parser`)
3. **Command Lookup**: Determine the potential process rule path (e.g., `system/help` from `> help`)
4. **Process Rule Fetching**: Use `fetch_rules` to get the specific process definition (MANDATORY).
5. **Permission Check**: Basic permission verification (e.g., can `fetch_rules` be called for this path). Detailed execution permissions are typically defined and checked within the fetched rule itself if needed.
6. **Delegated Execution**: If `fetch_rules` is successful, the `command-handler` yields. The AI assistant (interpreter) then directly executes the tool calls and logic defined *within the fetched process rule*.
7. **Response Handling**: The AI assistant (interpreter) handles the response generated by the execution of the fetched process rule, formatting it as needed.

### Command Detection

```javascript
// Check if user input is a command (starts with >)
function isCommand(input) {
  // Remove leading whitespace
  const trimmedInput = input.trim();
  
  // Check if it starts with >
  return trimmedInput.startsWith('>');
}
```

### Command Tokenization

```javascript
// Parse command into components
function parseCommand(input) {
  // Remove > prefix and trim whitespace
  const commandString = input.trim().substring(1).trim();
  
  // Initialize result object
  const result = {
    command: '',
    subcommand: '',
    args: [],
    flags: {}
  };
  
  // Split into tokens
  const tokens = commandString.match(/(?:[^\s"]+|"[^"]*")+/g) || [];
  
  // First token is the command
  if (tokens.length > 0) {
    result.command = tokens[0];
    
    // Second token is the subcommand if it doesn't start with -- and isn't preceded by a flag
    if (tokens.length > 1 && !tokens[1].startsWith('--')) {
      result.subcommand = tokens[1];
      
      // Remaining tokens are args or flags
      for (let i = 2; i < tokens.length; i++) {
        const token = tokens[i];
        
        if (token.startsWith('--')) {
          // Flag with value
          if (i < tokens.length - 1 && !tokens[i+1].startsWith('--')) {
            result.flags[token.substring(2)] = tokens[i+1];
            i++; // Skip the value token
          } else {
            // Flag without value (boolean flag)
            result.flags[token.substring(2)] = true;
          }
        } else {
          // Argument
          result.args.push(token);
        }
      }
    } else {
      // No subcommand, remaining tokens are args or flags
      for (let i = 1; i < tokens.length; i++) {
        const token = tokens[i];
        
        if (token.startsWith('--')) {
          // Flag with value
          if (i < tokens.length - 1 && !tokens[i+1].startsWith('--')) {
            result.flags[token.substring(2)] = tokens[i+1];
            i++; // Skip the value token
          } else {
            // Flag without value (boolean flag)
            result.flags[token.substring(2)] = true;
          }
        } else {
          // Argument
          result.args.push(token);
        }
      }
    }
  }
  
  return result;
}
```

### Process Lookup

```javascript
// Find the process file path relative to 00os/processes/
function findProcessPathRelative(command, subcommand) {
  // Order of checking categories
  const categories = ['system', '00reaper', '1000xdev'];
  
  // Explicit mappings (prioritize these)
  const explicitMappings = {
    'system': ['system', 'config', 'help', 'version', 'echo', 'state', 'chain', 'command-registry', 'file', 'cd', 'pwd', 'ls', 'calculator', 'file-list', 'file-read', 'file-search', 'system-monitor'],
    '00reaper': ['reaper-init', 'reaper-update', 'reaper-sync', 'reaper-read-files', 'reaper-analyze-tasks', 'reaper-implement'],
    '1000xdev': [] // Placeholder for future 1000xdev commands
  };

  // Check explicit mappings first
  for (const category of categories) {
    if (explicitMappings[category] && explicitMappings[category].includes(command)) {
      let path = `${category}/${command}`;
      if (subcommand) path += `-${subcommand}`;
      return path + '.md';
    }
  }

  // Fallback logic: Try to guess category based on prefix, then default to system
  let guessedCategory = 'system'; // Default category
  if (command.startsWith('reaper-')) {
      guessedCategory = '00reaper';
  } else if (command.startsWith('dev-')) { // Example future prefix
      guessedCategory = '1000xdev';
  }
  
  let fallbackPath = `${guessedCategory}/${command}`;
  if (subcommand) fallbackPath += `-${subcommand}`;
  
  // The fetch_rules call will ultimately determine if the file exists at the constructed path.
  // This function just provides the best guess for the path structure.
  tools.log(`Process path for '${command}${subcommand ? '-' + subcommand : ''}' determined as: '${fallbackPath}.md' (using fallback logic)`);
  return fallbackPath + '.md';
}
```

### Detect Self-Execution Patterns

```javascript
// Check if a command is attempting to execute another 00OS command through terminal commands
// This pattern creates infinite loops and should be avoided.
function isSelfExecutionAttempt(flags, args) {
  // Basic check: Look for '> ' pattern within arguments or known command flags
  const commandPattern = /\\s*>\\s+/; // Matches '> ' potentially with surrounding whitespace

  // Check flags that might contain commands
  if (flags.command && typeof flags.command === 'string' && commandPattern.test(flags.command)) {
    tools.warn(`Potential self-execution pattern detected in flags: ${JSON.stringify(flags)}`);
    return true;
  }
   if (flags.commands && typeof flags.commands === 'string' && commandPattern.test(flags.commands)) {
    tools.warn(`Potential self-execution pattern detected in flags: ${JSON.stringify(flags)}`);
    return true;
  }

  // Check arguments
  for (const arg of args) {
    if (typeof arg === 'string' && commandPattern.test(arg)) {
      tools.warn(`Potential self-execution pattern detected in arguments: ${arg}`);
      return true;
    }
  }

  return false;
}
```

### Legacy Command Support

```javascript
// Check if the input is a legacy command
function isLegacyCommand(input) {
  return input.trim().startsWith('run command:');
}

// Convert legacy command to new format
function convertLegacyCommand(input) {
  // Extract the command path
  const commandPath = input.trim().substring('run command:'.length).trim();
  
  // Split into domain and command
  const [domain, command] = commandPath.split('/');
  
  // Map to new command format
  if (domain === 'system') {
    return `> system ${command}`;
  } else if (domain === 'tools') {
    return `> tools ${command}`;
  } else if (domain === 'frontend') {
    return `> frontend ${command}`;
  } else if (domain === 'backend') {
    return `> backend ${command}`;
  } else {
    // Default mapping
    return `> ${domain} ${command}`;
  }
}
```

## Main Processing Function

```javascript
// Main function to process a command
async function processCommand(input) {
  // Check if this is a command
  if (!isCommand(input)) {
    // Check if it's a legacy command
    if (isLegacyCommand(input)) {
      // Convert and process as new command
      return processCommand(convertLegacyCommand(input));
    }

    // Not a command, return null to let the system handle it normally
    return null;
  }

  try {
    // Parse the command
    const parsedCommand = parseCommand(input);
    const commandFullName = `${parsedCommand.command}${parsedCommand.subcommand ? ' ' + parsedCommand.subcommand : ''}`;
    tools.log(`Processing command: ${commandFullName}`);

    // Verify this is not a self-execution attempt
    if (isSelfExecutionAttempt(parsedCommand.flags, parsedCommand.args)) {
      tools.error(`Detected attempt to execute 00OS command within '${commandFullName}'`);
      return formatResponse(`Error: Self-execution of 00OS commands is not allowed.\n      \nSuggestions:\n- Do not try to execute 00OS commands (prefixed with >) within other commands or arguments.\n- Each command must be executed separately.\n- Use '> chain [command1] | [command2]' for sequences.`, false);
    }

    // Determine the expected process path relative to 00os/processes/
    const relativeProcessPath = findProcessPathRelative(parsedCommand.command, parsedCommand.subcommand);
    
    // Construct rule name for fetch_rules (relative path without leading slash or extension)
    // Example: system/help.md -> processes/system/help
    const ruleNameForFetch = `processes/${relativeProcessPath.replace(/\\.md$/, '')}`;
    tools.log(`Attempting to fetch rule: ${ruleNameForFetch}`);

    try {
        // Fetch the rule - this is MANDATORY for all command processing
        const fetchResult = await tools.call('fetch_rules', {
            rule_names: [ruleNameForFetch],
            explanation: `Fetching process rule '${ruleNameForFetch}' to handle the command '${commandFullName}'.`
        });

        // Check if fetch_rules actually returned the process rule content
        // Note: A successful call might still return an empty result if the rule wasn't found or accessible.
        if (!fetchResult || !fetchResult.results || fetchResult.results.length === 0 || !fetchResult.results[0]) {
             tools.error(`fetch_rules call succeeded but did not return content for rule '${ruleNameForFetch}'.`);
             throw new Error(`Process rule '${ruleNameForFetch}' not found or is empty.`);
        }
        
        tools.log(`Successfully fetched rule: ${ruleNameForFetch}`);

        // Check permissions before execution (future integration point)
        if (!checkPermissions(parsedCommand.command, parsedCommand.subcommand)) {
          return formatResponse(`Error: You don't have permission to execute this command.`, false);
        }

        // At this point, the fetched rule contains the necessary execution logic
        // The AI assistant will now execute the logic defined within the fetched rule.
        // This handler's job is done after successfully fetching the rule.
        return {
          status: "command_fetched",
          command: parsedCommand.command,
          subcommand: parsedCommand.subcommand,
          args: parsedCommand.args,
          flags: parsedCommand.flags,
          processRule: ruleNameForFetch // Return the fetched rule name for context
        };
    } catch (fetchError) {
        // If fetch_rules fails or returns no content, this is a critical error.
        tools.error(`Failed to fetch rule for process path '${relativeProcessPath}': ${fetchError.message}`);

        // Provide more specific feedback if the error indicates "not found"
        if (fetchError.message.includes('not found') || fetchError.message.includes('failed to load')) {
            const categoryHelp = getProcessCategoryHelp(parsedCommand.command);
            return formatResponse(`Command '${commandFullName}' not found.\nCould not find or load the corresponding process rule at '00os/processes/${relativeProcessPath}'.\n            \nSuggestions:\n- Verify the command spelling and arguments.\n- Ensure the process file '.md' exists at the expected path within the '00os/processes/' directory.\n- Check that the file name matches the command name (lowercase, hyphens for spaces).\n- Use '> help' to list available commands.${categoryHelp ? '\\n' + categoryHelp : ''}\n- Run '> reaper-sync' if you recently added/modified the process file.`, false);
        }

        // Generic error for other fetch failures
        return formatResponse(`Command '${commandFullName}' could not be processed due to an internal error while fetching its definition.\nError details: ${fetchError.message}\n        \nSuggestions:\n- Try the command again later.\n- Use '> help' to see if the command is listed.\n- Report this issue if it persists.`, false);
    }
  } catch (error) {
    // Handle general command parsing or unexpected errors before fetch_rules
    tools.error(`Error processing command '${input}': ${error.message}`);
    return formatResponse(`Error parsing or processing command: ${error.message}\n    \nSuggestions:\n- Check the command syntax (e.g., quotes, flags).\n- Try using '> help' for command usage information.`, false);
  }
}

// Helper function to provide category-specific help messages
function getProcessCategoryHelp(command) {
    // Use the same mappings as findProcessPathRelative for consistency
    const explicitMappings = {
      'system': ['system', 'config', 'help', 'version', 'echo', 'state', 'chain', 'command-registry', 'file', 'cd', 'pwd', 'ls', 'calculator', 'file-list', 'file-read', 'file-search', 'system-monitor'],
      '00reaper': ['reaper-init', 'reaper-update', 'reaper-sync', 'reaper-read-files', 'reaper-analyze-tasks', 'reaper-implement'],
      '1000xdev': []
    };

    for (const category in explicitMappings) {
        if (explicitMappings[category].includes(command)) {
            return `- This command should correspond to a process file in '/00os/processes/${category}/'`;
        }
    }
    if (command.startsWith('reaper-')) {
        return "- Commands starting with 'reaper-' should be in '/00os/processes/00reaper/'";
    }
     if (command.startsWith('dev-')) { // Example future prefix
        return "- Commands starting with 'dev-' should be in '/00os/processes/1000xdev/'";
    }
    // Default if no match
    return "- Ensure the process file is in the correct category subfolder (system, 00reaper, or 1000xdev).";
}
```

## Integration with Cursor Rules

This command handler integrates with the Cursor rules system by intercepting user input before it's processed by the general knowledge base. When a message is identified as a command (starting with `>`), it's routed through this handler instead of being treated as a regular message.

This allows 00OS to transform the prompt box into a terminal interface while maintaining the ability to have regular conversations when needed.

## Fallback Mechanism

If a command isn't recognized or can't be processed, the system provides helpful error messages and suggestions:

```
❌ Error: Command 'unknown' not found
Suggestions:
- Use 'help' to see available commands
- Check the spelling of your command
- Try 'system list-commands' to see all available commands
```

## Example Command Flows

1. **Basic Command**: `> help`
   - Detected as a command
   - Parsed: command="help", no subcommand, no args, no flags
   - Process: `/00os/processes/system/help.md`
   - Result: Help system output

2. **Command with Subcommand**: `> file list /00os/processes`
   - Detected as a command
   - Parsed: command="file", subcommand="list", args=["/00os/processes"]
   - Process: `/00os/processes/system/file-list.md`
   - Result: List of files in the processes directory

3. **Legacy Command**: `run command:system/status`
   - Detected as a legacy command
   - Converted to: `> system status`
   - Processed as a new-format command

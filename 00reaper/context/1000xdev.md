# 1000xdev Workflow Context (Current State)

This file provides a detailed, up-to-date snapshot of the 1000xdev workflow, documentation hub, standards, and key context files. It is designed to support rapid onboarding, daily productivity, and continuous improvement for all 1000xdev, front-end, and back-end development in the GigaSwap project.

---

## 1000xdev Workflow Overview
- **AI Identity:** 1000xdev is the autonomous application code agent for GigaSwap, focused on rapid, standards-driven development and integration, especially for Steam API and CS2 marketplace features.
- **Workflow Folder:** All workflow, documentation, and context are under `1000xdev/`.
- **Documentation Hub:** The `1000xdev/documentation/` folder is a modular, living resource for onboarding, workflow standards, technical reference, and best practices. It is organized into:
  - `front-end-architecture/`: Onboarding and reference for front-end (React/Next.js, UI, client logic)
  - `back-end-architecture/`: Onboarding and reference for back-end (FastAPI, database, business logic)
  - `full-stack-workflow/`: Project-wide onboarding, architecture, and business context
  - `steam/`: All onboarding, technical, and research docs for Steam API integration
  - `cursor-rules/`: Reference for all Cursor rules, conventions, and AI workflow standards
  - `1000xdev-identity/`: Identity, philosophy, and operational boundaries for 1000xdev

---

## Principles
- Modular, standards-driven, and continuously improved documentation and workflow
- All major integration, testing, and implementation processes are documented and standardized
- Designed for rapid onboarding, codebase analysis, and autonomous agent development
- Documentation is actionable, discoverable, and up-to-date; legacy or empty files are removed or updated each cycle
- The documentation hub is reviewed and improved every cycle, especially during Step 5 (Update Supporting Materials)

---

## Cyclical Workflow & Progress Tracking
- 1000xdev follows a strict 6-step cyclical workflow for all development cycles (see `1000xdev-brain.md` for details)
- All planning, requirements, and implementation progress are tracked in `planning/active-request.md` and `cycle-status.md`
- The `cycle-status.md` file now includes a granular subtask tracker for Step 4 (Make Changes) and a status checklist for at-a-glance progress
- All major changes, rationale, and lessons learned are logged in the cycle-status action log

# Communication Standards Guideline

## General Standards

1.  1000xdev uses professional, technical terminology.
2.  It maintains the consistent voice defined in `1000xrules/core/identity/core-identity.md`.
3.  It is concise but thorough in explanations (primarily in documentation like plans, knowledge files, and READMEs).
4.  It provides clear rationale for implementation decisions (in documentation).
5.  It documents limitations and potential issues encountered.

## Implementation Status Communication

When communicating implementation status (e.g., updating `1000xplans/<domain>/implementation-progress.md` or logging to `1000xbrain/<domain>/operational_feedback/`):

1.  Reference specific files and components affected.
2.  Summarize changes made and their purpose.
3.  Note any challenges or limitations encountered.
4.  Provide verification steps taken.
5.  Recommend follow-up actions if needed.

(See also Proposal 5.8 in `1000xplans/system/plan.md` for specific feedback loop conventions.)
